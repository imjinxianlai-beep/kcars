# CRM 交接部署与维护

目标：继续使用现有 Vercel 网站和 Supabase 数据库。代码库、Vercel、Supabase 仍由所有者掌握。同事只有应用内查询和导入权限，无需获得仓库或数据库控制台权限。

## 已验证与上线顺序

本地测试使用隔离的 PGlite PostgreSQL；`npm test` 验证权限、重复导入、事务回滚、缺车牌续导和登录服务边界。真实 Excel 只用于本地解析核对，不会自动导入正式库。

上线前只读检查已确认正式库与所有者认证账号。最终上线前再次记录数量，避免将其他人的同期更新误当作本次变化。

1. `npm ci`、`npm test`；使用 Deno 检查两个函数。Node 24 支持测试中的 TypeScript stripping。
2. 构建前确认 `VITE_SUPABASE_URL` 指向上述正式项目，且 `VITE_SUPABASE_ANON_KEY` 是同项目的公开客户端密钥。现有本地 `.env` 是旧 demo，不可直接作为生产构建配置。任何 `service_role` 密钥都不能以 `VITE_` 开头。
3. 准备 Vercel 预览部署，不先替换正式站。只有预览构建通过、数据库迁移和认证服务准备好后，再推广生产版本。
4. 在正确项目部署 `supabase/functions/crm-login/index.ts` 与 `crm-account/index.ts`。配置见 `supabase/config.toml`；两个端点自行校验身份，网关 `verify_jwt=false`。`crm-account` 必须先验证登录令牌、数据库管理员角色，才可创建账号。服务密钥仅使用 Supabase 自动注入的服务端环境变量。
5. 将 `select set_config('kcars.bootstrap_admin_email','<已确认的所有者登录邮箱>',false);` 放在 `supabase/migrations/20261119_handover.sql` 前，在同一次运行中完整执行。该脚本使用事务，任何错误回滚；不得运行 `supabase/schema.sql` 或 seed 文件。
6. 确认 `crm_members` 中 `owner` 为启用的 admin；`crm_my_profile` 在本人会话返回 admin。使用匿名密钥读取 CRM 表应被拒绝，未分配成员的登录用户不能读数据。
7. 推广前端至生产。先验证所有者登录、旧 CRM 页面、查询，再通过“账号管理”创建 Jonathan。同事账号不能修改历史发票、删除数据、管理账号；直接调用数据库也受同样限制。
8. 验证同事查询和两份文件的预览；只有核对过的新月数据才确认导入。不用正式库做虚构数据写入测试。
9. 交接固定网址、用户名和《同事每月更新说明》。密码单独交付。

权限迁移会关闭旧匿名访问：独立的匿名 Plate Scanner 页面需改用登录后的查询页。已有登录的所有者仍有原有管理功能。

## 数据规则与维护

- 原始工作簿保存在私有 `crm-imports` Storage 桶；上传者和管理员可以读取。应用用户不能替换、删除原件。
- 导入预览、结果和事件保存在 `crm_import_*` 表。首次保存批次不改变 CRM 数据。
- 按发票号去重，确认时在事务内重新检查；已有发票不会被覆盖。行数、金额核对失败时整个确认事务回滚。
- 只为需要的新客户、车辆、发票及明细新增记录；不会按导入内容修改老客户资料。存在车牌关联冲突的记录进入待处理。
- 缺车牌可在未导入时补充一次。其他异常修正源文件后重新上传；旧批次留作审计。
- 数量乘单价与行金额允许 0.01 的舍入差；金额最多两位小数。历史导入保持折扣和免费项目。
- 管理员可在“账号管理”停用同事；数据库下一次请求立即失去访问权限，页面最多一分钟刷新角色状态。
- 应用不会自动清理历史原件、批次、事件或私有快照；管理员应监测 Supabase 存储容量并制定备份/保留期限。
- 原件哈希是客户端提交的审计元数据，不能当作独立的服务端内容认证。数据库对提交字段、权限和金额独立校验。

## 出错与恢复

迁移失败：事务回滚，不要跳过错误继续分段执行。先检查正确项目、所有者账号、实际表结构。

前端失败：Vercel 可回退上一版部署。旧版所有者邮箱登录仍受新的成员权限保护。不要为了恢复旧匿名工具而开放数据库权限。

迁移保存了旧公共表授权、RLS 策略和相关对象定义到私有 `kcars_private.permission_backup`，供维护人员定点恢复。避免自动恢复历史上可能过宽的授权。

导入失败：先读取批次结果，确认未提交或已完成，再重试。提交是原子事务，断网不代表未成功。导入前匹配的记录快照存入私有 `kcars_private.import_snapshots`；每条新发票关联导入明细与批次。若确需撤销一次成功导入，由管理员审查后处理，不提供同事批量删除入口。

本地页面演示：`node scripts/preview-handover.mjs`，访问 `http://127.0.0.1:5174`。该入口只加载虚构数据，拒绝上传和写入；测试替换仅在这个脚本中启用，不参与正常 Vite/Vercel 构建。
